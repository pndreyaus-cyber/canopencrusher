# CANCrusher: краткий обзор файлов проекта

Этот проект — прошивка контроллера робота, который управляет приводами через CANopen. Общая идея простая:

- компьютер или внешний хост отправляет команды по последовательному порту;
- `CANCrusher.ino` принимает и разбирает эти команды;
- `MoveControllerBase` превращает задачу движения в целевые положения осей и параметры траектории;
- `CanOpen` отправляет нужные команды приводам по CAN;
- приводы возвращают текущее положение и статус;
- для движения в пространстве используется кинематика (`Solver4AxesAlwaysVertical`), которая переводит между суставными и декартовыми координатами.


## Основные файлы

### CANCrusher.ino
Это главный файл прошивки и "диспетчер команд". Он инициализирует CAN, последовательный порт, IO выходы,, а затем работает в основном цикле `loop()`. По сути, этот файл слушает команды вроде `MAJ`, `JPD`, `RPC`, `ZOE`, `RMS`, `PIR`, `PIW` и вызывает нужную обработку: движение, сброс нуля, чтение статуса, настройку параметров и т.д.


### CanOpen.h / CanOpen.cpp
Это слой низкоуровневой CANopen-коммуникации. По сути прослойка между интерфейсом библиотеки STM32_CAN и прошивкой робота. Здесь реализованы отправка и прием CAN-сообщений, а также преобразование высокоуровневых команд в SDO/PDO сообщения для приводов. Этот слой отвечает за запись управляющего слова, настройку режима работы, целевую позицию, профиль скорости и ускорения, обработку heartbeat и чтение статусного слова.



### CanOpenController.h
Здесь объявлены callback-функции и обработчики сообщений, которые приходят по CAN шине.

Это позволяет движущей логике реагировать на события от приводов асинхронно (по очереди, обрабатывая каждое сообщение последовательно -- 1 раз за цикл), без жесткой привязки ко всем деталям протокола в каждом месте кода.

### MoveControllerBase.h / MoveControllerBase.cpp
Этот класс хранит состояние робота и меняет состояние робота. Здесь решается, как двигать каждую ось, проверяются лимиты, формируются профили скорости и ускорения, отслеживается статус движения, проверяется, что привод достиг целевой позиции, а также реализуются процедуры инициализации/обнуления и периодический опрос позиции во время движения.
### Axis.h / Axis.cpp
Это абстракция одной оси. Для каждой оси хранится node ID, текущее положение, целевая позиция, лимиты, скорость, ускорение, допуск и статус "жив/инициализирован/не инициализирован". Здесь также находятся функции пересчёта между шагами, градусами и оборотами в минуту.


### KinematicSolver.h
Это общий интерфейс решения обратной и прямой задач кинематики робота. В нём определены структуры для углов суставов (`JointAngles`) и положения в пространстве (`Position`), а также базовый контракт для обратной кинематики (`ik`) и прямой кинематики (`fk`).



### Solver4AxesAlwaysVertical.h
Одно из решений задачи кинематики. Здесь описан алгоритм преобразования между целевой точкой в пространстве и углами суставов, а также проверка, что целевая точка достижима в пределах механики робота. Это модель для 4-осевого манипулятора, у которого 4-ая ось всегда направлено параллельно горизонту и смотрит внизв.


### RobotConstants.h
Это файл, содержащий основные параметры робота. Здесь задаются пины, скорость CAN, названия команд (`MAJ`, `JPD`, `RPC`, `ZOE` и т.п.), идентификаторы моторов, единицы измерения, число осей, перечисления состояний и множество параметров, специфичных для этой машины.


### Params.h
В этом файле лежат структуры данных, которые используются для разбора входных параметров команд. Например `MoveParams`, `SpeedAcceleration`, `MotorIndex`, `PIValue`, `MoveToleranceWrite`.


### OD.h / OD.cpp
Это автоматически сгенерированный объектный словарь CANopen из EDS-файла. Он описывает индексы объектов, subindex, mapping PDO, SDO-объекты и регистры приводов.

Во-первых, этот класс был создан автоматически и не надо было его вручную писать. Во-вторых, объект этого класса повторяет параметры, которые находятся в соответствующем моторе. По идее, чтобы узнать что-то на моторе надо посмотреть на значение переменной соответствующего объекта класса

В них есть 1 структура, которая называется OD_RAM_t. Она как раз хранит состояние мотора -- скорость, позицию, настройки ПИ-регулятора и другие

И также есть 1 метод, который называется init_od_ram(OD_RAM_t *obj). Он заполняет поля obj дефолтными значениями



### objdict_objectdefines.h
Это сгенерированные символьные имена для объектов словаря CANopen. Вместо того чтобы писать шестнадцатеричные адреса вручную, код использует имена вроде `_Controlword_Controlword_sIdx` и `_Target_position_Target_position_sIdx`.

Это делает код читаемым и уменьшает риск ошибок при работе с адресами регистров.

### Debug.h / DebugConfig.h
Кратко: это инфраструктура отладки. Макросы позволяют выводить события по движению осей, CANopen-коммуникации, инициализации и сериалу. `DebugConfig.h` выбирает, какие группы сообщений включены и на каком уровне подробности.

Сгенерировано ИИ. Использовалось, чтобы для отладки не все возможные отладочные сообщения выводить, а только необходимые. Вдобавок, есть проблема, когда пишешь много в Serial, он ломается и начинает выдавать бред

### hal_conf_extra.h
Это вспомогательный файл настройки HAL для платформы STM32. Он не содержит логику управления роботом. Он включает настройки периферии, связанных с CAN, и содержит замечания про совместное использование USB/CAN и remapping прерываний на некоторых семействах STM3
1. хост или ПК отправляет команду по UART/Serial;
2. `CANCrusher.ino` принимает и парсит её;
3. `MoveControllerBase` превращает запрос в набор целевых положений для осей и параметры профиля движения;
4. `Axis` хранит лимиты и текущие цели для каждой оси;
5. `CanOpen` формирует корректные CANopen-фреймы для приводов;
6. приводы выполняют движение и возвращают позицию/статус;
7. контроллер продолжает опрос до завершения перемещения или таймаута;
8. для движения в декартовом пространстве `Solver4AxesAlwaysVertical` сначала переводит заданную точку в углы суставов.

То есть в общем виде программа — это:

- интерпретатор команд;
- решатель кинематики;
- конечная автоматика движения через CANopen.

## Где лучше всего начать, если нужно переписать проект

Если кто-то будет писать новую версию с нуля, самые полезные файлы для чтения — это:

- `CANCrusher.ino` — общий поток управления;
- `MoveControllerBase.h / MoveControllerBase.cpp` — состояние движения и алгоритм перемещения;
- `Solver4AxesAlwaysVertical.h` — геометрия и кинематика робота;
- `CanOpen.h / CanOpen.cpp` — общение с приводами по CAN;
- `RobotConstants.h` — все параметры и протокол этой конкретной машины.

Эти файлы объясняют самого "смысл" программы гораздо лучше, чем автоматически сгенерированный словарь объектных регистров.
